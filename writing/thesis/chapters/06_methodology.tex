\chapter{Methodology}\label{chap:methodology}

Evolutionary loops operating over stochastic fitness evaluations suffer from deceptive selection signals. When objective returns carry variance, candidate algorithms easily exploit lucky evaluation samples, which stalls code generation routines that rely on reliable directional feedback. Resolving this failure mode requires an execution environment that isolates stochastic noise during candidate evaluation while maintaining clean progress metrics for outer-loop selection.

This chapter establishes the mathematical specifications, execution sandboxing, and statistical protocols of the automated algorithm design system. First, we formalize the optimality-gap heteroscedastic noise model and trace its behavior across representative continuous topologies. We then define the dual-evaluation decoupling layer that isolates candidate search logic from diagnostic telemetry, followed by the Abstract Syntax Tree (AST) validation rules, execution timeouts, and traceback recovery pipelines. Subsequent sections detail the evolutionary selection operators, the stochastic parent resampling policy ($K=3$), and the prompt scaffolding configurations evaluated in our experiments. We conclude by specifying the orchestration lifecycle and the non-parametric statistical hypothesis testing protocol used for empirical verification.

\section{System Orchestration}\label{sec:method_orchestration}

The interaction between the heteroscedastic noise model, sandboxed execution, prompt scaffolding, and parent resampling forms a closed-loop search system.

\begin{figure}[htbp]
\centering
\input{figures/evolutionary_aad_loop}
\caption{System orchestration of the stochastic Automated Algorithm Design loop. Source code flows from the model through AST validation to the execution sandbox. Search decisions consume noisy evaluations $f_{\text{noisy}}(x_k)$, while the background logger records true precision $\Delta f(x_k)$ and applies parent resampling ($K=3$, $\bar{f}_{\text{parent}}$) to update prompt context $\mathcal{C}_g$.}
\label{fig:evolutionary_aad_loop}
\end{figure}

Each generation $g \in \{1 \dots G\}$ proceeds through five phases:
\begin{enumerate}
\item \textbf{Context Assembly and Generation:} The driver builds prompt packet $\mathcal{C}_g$ (Equation~\ref{eq:context_assembly}) containing the chosen prompt archetype, parent code $\mathcal{A}_{\text{parent}}$, and prior error traces. The model mutates the parent to produce $\mathcal{A}_{\text{child}}$.
\item \textbf{Sanitization and Validation:} The harness extracts the code block using regular expressions and parses the AST. Scripts with unauthorized imports or blacklisted built-ins receive $\mathcal{F} = -10^9$ and terminate immediately.
\item \textbf{Decoupled Execution:} The validated candidate executes inside an isolated worker under budget $B = 100\,000$ and timeout $T_{\text{max}} = 10.0\,\text{s}$. The candidate receives noisy values $f_{\text{noisy}}(x_k)$ (Equation~\ref{eq:wrapper_noise_return}), while the background harness logs uncorrupted spatial error $\Delta f(x_k)$ (Equation~\ref{eq:clean_distance_metric}).
\item \textbf{Error Handling and Oracle Scoring:} If execution fails or times out, the run receives tiered penalty $\mathcal{F}_{\text{failure}}$ (Equation~\ref{eq:failure_penalties}), and the formatted traceback appends to $\mathcal{T}_{\text{feedback}}$. If execution completes, final coordinate $\mathbf{x}^*$ is evaluated on clean oracle $f_{\text{clean}}(\mathbf{x}^*)$ to assign scalar fitness $\mathcal{F}(\mathcal{A}_{\text{child}})$ via Equation~\ref{eq:meta_fitness_score}.
\item \textbf{Selection and Parent Resampling:} Child fitness $\mathcal{F}(\mathcal{A}_{\text{child}})$ is compared against incumbent score $\bar{\mathcal{F}}_{\text{parent}}$. If $\mathcal{F}(\mathcal{A}_{\text{child}}) > \bar{\mathcal{F}}_{\text{parent}}$, the child becomes the candidate parent. The incumbent is re-evaluated across $K = 3$ stochastic runs to update baseline $\bar{\mathcal{F}}_{\text{parent}}$ (Equation~\ref{eq:parent_resampling}), and the history archive $\mathcal{H}_{1 \dots g}$ logs the step.
\end{enumerate}

\section{Noise Modeling}\label{sec:noise_modeling}

Automated synthesis of noise-resilient continuous heuristics requires benchmarking against stochastic fitness surfaces \cite{Jin2005}. We use the continuous Black-Box Optimization Benchmark (BBOB) suite as our base testbed \cite{Hansen2010}. Because standard BBOB functions evaluate deterministically, the execution wrapper must inject controlled variance directly at the interface level.

In experimental optimization and physical engineering domains---such as chemical process control, wind turbine aerodynamics, and physical sensor telemetry---observed measurement uncertainty rarely stems from a single isolated source. Instead, it arises from the continuous aggregation of countless independent micro-disturbances. By the Central Limit Theorem (CLT), the sum of these independent stochastic errors naturally converges to a normal distribution, establishing additive Gaussian noise $\mathcal{N}(0, \sigma^2)$ as the most physically realistic model for continuous search environments \cite{Shir2012, Spall2003}.

Beyond physical realism, zero-mean Gaussian perturbations guarantee an unbiased mathematical expectation ($\mathbb{E}[z] = 0$). Consequently, the expected value of any corrupted observation strictly equals the underlying true objective elevation: $\mathbb{E}[f_{\text{noisy}}(x)] = f_{\text{clean}}(x)$ \cite{Spall2003}. This unbiased property is vital for Automated Algorithm Design: it ensures that if the language model successfully synthesizes noise-mitigation mechanics---such as Monte Carlo sample averaging ($\frac{1}{K} \sum_{i=1}^K f_{\text{noisy}}(x_i)$) or momentum-based filtering---the heuristic will consistently converge toward the true uncorrupted mean without accumulating systematic mathematical bias.

In the optimization literature, Gaussian uncertainty is commonly formulated either as homoscedastic static additive noise \cite{Jin2005}:
\begin{equation}\label{eq:static_noise_lit}
    f_{\text{noisy}}(x) = f_{\text{clean}}(x) + \mathcal{N}(0, \sigma^2)
\end{equation}
or through point-wise multiplicative variance \cite{Jin2005}:
\begin{equation}\label{eq:naive_multiplicative_lit}
    f_{\text{noisy}}(x) = f_{\text{clean}}(x) \cdot \left(1 + \mathcal{N}(0, \text{CV}^2)\right)
\end{equation}
where $x \in \mathbb{R}^D$ denotes a $D$-dimensional coordinate vector, $f_{\text{clean}}(x) \in \mathbb{R}$ is the true objective value, $\sigma^2 \in \mathbb{R}^+$ is a fixed variance, $\text{CV} \in \mathbb{R}^+$ is the dimensionless Coefficient of Variation ($\text{CV} = \sigma / \mu$), and $f_{\text{noisy}}(x) \in \mathbb{R}$ represents the corrupted signal returned to the optimizer.

Both formulations break down across heterogeneous benchmark suites \cite{Hansen2010}. Homoscedastic additive noise (Equation~\ref{eq:static_noise_lit}) applies constant variance regardless of objective magnitude. Near the optimum where objective values drop to $10^{-5}$, this constant variance produces an overwhelmingly low Signal-to-Noise Ratio (SNR) that obliterates descent gradients. Conversely, on steep sections where objective values exceed $10^6$, the identical additive variance becomes negligible, allowing optimizers to converge without developing explicit noise-filtering routines \cite{Hansen2010}.

Multiplicative noise (Equation~\ref{eq:naive_multiplicative_lit}) introduces a different artifact by scaling variance directly against raw elevation $f_{\text{clean}}(x)$. This formulation includes any vertical translation $f(x^*)$ added to the global minimum. Adding a vertical offset $g(x) = f(x) + 10\,000$ scales the variance by orders of magnitude, corrupting the local basin structure without altering the underlying spatial topography.

BBOB function $f_{21}$ (Gallagher's Gaussian 101 Peaks) highlights the ranking vulnerability of naive multiplicative and homoscedastic models. The global minimum sits at an analytical offset of $f(x^*) \approx 40.78$, across a total dynamic range of roughly 50 units. Under naive multiplicative noise with $\text{CV} = 0.05$, a coordinate evaluated near the global optimum at $f_{\text{clean}}(x) = 41.0$ yields a standard deviation of:
\begin{equation}\label{eq:f21_naive_std}
    \sigma = 0.05 \cdot 41.0 = 2.05
\end{equation}
This deviation spans $4\%$ of the total function range. Because peak elevation gaps in $f_{21}$ span only $2$ to $5$ units, this variance erases local basin boundaries. Evaluating adjacent coordinates $x_a$ ($f_{\text{clean}} = 41.5$) and $x_b$ ($f_{\text{clean}} = 42.0$) produces heavily overlapping distributions: $f_{\text{noisy}}(x_a) \sim \mathcal{N}(41.5, 2.075^2)$ and $f_{\text{noisy}}(x_b) \sim \mathcal{N}(42.0, 2.1^2)$. Stochastic draws frequently invert the true ranking ($f_{\text{noisy}}(x_a) > f_{\text{noisy}}(x_b)$), depriving search routines of usable directional signals.

We resolve these discrepancies using a Heteroscedastic Optimality-Gap Noise Model. Rather than scaling variance against arbitrary raw function values, variance is tied directly to the distance from the global minimum. For any coordinate $x_k \in \mathbb{R}^D$ queried at step $k$, the local standard deviation $\sigma_{\text{dynamic}}(x_k)$ scales strictly with the absolute optimality gap:
\begin{equation}\label{eq:proportional_dynamic_std}
    \sigma_{\text{dynamic}}(x_k) = \text{CV} \cdot \left| f_{\text{clean}}(x_k) - f(x^*) \right|
\end{equation}
where $\text{CV} \ge 0$ parameterizes the noise severity (corresponding to the standard deviation scale in the execution wrapper), and $\left| f_{\text{clean}}(x_k) - f(x^*) \right|$ is the true spatial error.

The benchmark harness preserves the true minimum $f(x^*)$ internally while hiding it from the generated Python script. At evaluation step $k$, the candidate receives a corrupted scalar observation:
\begin{equation}\label{eq:proportional_gaussian_noise}
    f_{\text{noisy}}(x_k) = f_{\text{clean}}(x_k) + z_k, \quad z_k \sim \mathcal{N}\left(0, \sigma_{\text{dynamic}}^2(x_k)\right)
\end{equation}
where $z_k \in \mathbb{R}$ is an independent Gaussian perturbation sampled with density:
\begin{equation}\label{eq:gaussian_pdf_dynamic}
    p(z_k) = \frac{1}{\sqrt{2\pi \sigma_{\text{dynamic}}^2(x_k)}} \exp\left( -\frac{z_k^2}{2\sigma_{\text{dynamic}}^2(x_k)} \right)
\end{equation}
Because $p(z_k)$ is symmetric with zero expectation ($\mathbb{E}[z_k] = 0$), the noisy evaluation acts as an unbiased estimator of true fitness:
\begin{equation}\label{eq:unbiased_expectation}
    \mathbb{E}[f_{\text{noisy}}(x_k)] = f_{\text{clean}}(x_k)
\end{equation}

To maintain a strict black-box operational contract, the analytical minimum $f(x^*)$ and the runtime calculation of $\sigma_{\text{dynamic}}(x_k)$ remain strictly encapsulated within the execution wrapper. The candidate heuristic receives only the scalar float $f_{\text{noisy}}(x_k)$, preventing generated algorithms from introspecting the noise envelope or directly reverse-engineering the target coordinate. Furthermore, each query issued to the interface triggers an independent and identically distributed (i.i.d.) stochastic sample $z_k$. Re-evaluating the identical coordinate $x_k$ across $K$ consecutive queries yields uncorrelated realizations, allowing candidate heuristics that implement Monte Carlo resampling to suppress effective noise variance proportionally to $1/\sqrt{K}$.

Scaling variance heteroscedastically with the optimality gap provides two core properties for Automated Algorithm Design:
\begin{enumerate}
    \item \textbf{Scale Invariance:} The Signal-to-Noise Ratio remains bounded by $1/\text{CV}$ across varying benchmark ranges, from $f_8$ ($\sim 10^3$) to $f_{21}$ ($\sim 50$), removing the need to calibrate noise hyperparameters per function.
    \item \textbf{Structured Search Difficulty:} Regions far from the target exhibit high variance, while points close to the optimum narrow their variance profiles, matching empirical systems where measurement noise scales with distance from target equilibrium.
\end{enumerate}

Applying this model to $f_{21}$ ($\text{CV} = 0.05$), test coordinates $x_a$ ($f_{\text{clean}} = 41.5$) and $x_b$ ($f_{\text{clean}} = 42.0$) yield standard deviations of:
\begin{equation}\label{eq:f21_gap_std_a}
    \sigma_{\text{dynamic}}(x_a) = 0.05 \cdot |41.5 - 40.78| \approx 0.036
\end{equation}
\begin{equation}\label{eq:f21_gap_std_b}
    \sigma_{\text{dynamic}}(x_b) = 0.05 \cdot |42.0 - 40.78| \approx 0.061
\end{equation}
The resulting distributions, $f_{\text{noisy}}(x_a) \sim \mathcal{N}(41.5, 0.036^2)$ and $f_{\text{noisy}}(x_b) \sim \mathcal{N}(42.0, 0.061^2)$, preserve ranking order between both points and maintain usable descent vectors.

In contrast, the heteroscedastic optimality-gap formulation (Panel C) naturally tightens its variance envelope as coordinates approach the global minimizer $x^*$, preserving basin boundaries and retaining an actionable descent signal toward the global basin.

To evaluate behavior on large-scale, ill-conditioned geometries, consider BBOB function $f_8$ (Rosenbrock). Benchmark instances apply spatial translations $x^* \in \mathbb{R}^D$ and orthogonal rotation matrices $R \in \mathbb{R}^{D \times D}$ to eliminate coordinate alignment \cite{Hansen2010}:
\begin{equation}\label{eq:bbob_f8_formula}
    f_8(x) = \sum_{i=1}^{D-1} \left[ 100 \cdot \left( y_{i+1} - y_i^2 \right)^2 + (1 - y_i)^2 \right] + f_{\text{opt}}
\end{equation}
where $y = \max\left(1, \frac{\sqrt{D}}{8}\right) R (x - x^*) + \mathbf{1}$, $\mathbf{1} \in \mathbb{R}^D$ is a vector of ones, and $f_{\text{opt}} \in \mathbb{R}$ is the target minimum.

The term $100 \cdot (y_{i+1} - y_i^2)^2$ forms a steep parabolic valley, pushing boundary deviations $f_{\text{clean}}(x_k) - f_{\text{opt}}$ up to $10^3$. Setting $\text{CV} = 0.1$, exploration along domain boundaries where $f_{\text{clean}}(x_k) - f_{\text{opt}} \approx 10^3$ sets the standard deviation to:
\begin{equation}\label{eq:f8_dynamic_std_boundary}
    \sigma_{\text{dynamic}}(x_k) = 0.1 \cdot 10^3 = 10^2
\end{equation}
As search vectors enter the valley floor where $f_{\text{clean}}(x_k) - f_{\text{opt}} \approx 10^1$, the standard deviation drops proportionally:
\begin{equation}\label{eq:f8_dynamic_std_valley}
    \sigma_{\text{dynamic}}(x_k) = 0.1 \cdot 10^1 = 10^0
\end{equation}
By comparison, evaluating the isotropic sphere function $f_1(x) = \|R(x - x^*)\|^2 + f_{\text{opt}}$ near domain boundaries produces objective differences of $f_{\text{clean}}(x_k) - f_{\text{opt}} \approx 10^1$, yielding $\sigma_{\text{dynamic}} \approx 10^0$. Sampling noise through Equation~\ref{eq:proportional_gaussian_noise} yields perturbations $z_k \sim \mathcal{N}(0, \sigma_{\text{dynamic}}^2(x_k))$ that maintain equivalent relative SNR across diverse topographies.

Figure~\ref{fig:f8_noise_distortion} confirms this scaling behavior. The heteroscedastic optimality-gap formulation (Panel C) scales variance proportionally with objective magnitude across the entire coordinate range, maintaining balanced search difficulty from initial exploration down to local convergence.

\section{Evaluator Architecture and Execution Lifecycle}\label{sec:evaluator_architecture}

The evaluation harness governs execution containment, runtime exception handling, and ground-truth fitness assignment for candidate optimization routines \cite{LLaMEA2024}. Operating as an isolated wrapper around the benchmark objective, it intercepts execution faults and calculates true spatial convergence to guide the $(1+1)$ evolutionary search \cite{Arnold2003, Jin2005}.

Every heuristic synthesized by the language model must adhere to a standardized functional interface:
\begin{equation}\label{eq:candidate_interface_call}
    \mathbf{x}^*, y_{\text{raw}} = \operatorname{solve}(f, D, B_{\text{synth}}, \mathbf{lb}, \mathbf{ub})
\end{equation}
where $f$ denotes the callable objective wrapper, $D \in \{2, 3, 5\}$ specifies the continuous dimension, $B_{\text{synth}} = 1{,}000$ defines the function call budget during evolutionary synthesis, and $\mathbf{lb}, \mathbf{ub} \in \mathbb{R}^D$ define hypercube domain boundaries ($[-5.0, 5.0]^D$) \cite{Hansen2010, LLaMEA2024}.

During synthesis, candidate algorithms execute against the target optimization instance using exclusively the allocated budget of $B_{\text{synth}} = 1{,}000{,}000$ function evaluations \cite{LLaMEA2024}. Throughout the run, the heuristic interacts strictly with corrupted observations $f_{\text{noisy}}(x_k)$ generated via the optimality-gap heteroscedastic noise model (Equation~\ref{eq:proportional_gaussian_noise}), operating without analytical gradients, clean objective feedback, or prior knowledge of the global minimum $f^*$ \cite{Hansen2010, Jin2005}.

Upon exhausting its allocation of $B_{\text{synth}}$ evaluations, the candidate returns its best-identified spatial coordinate $\mathbf{x}^* \in \mathbb{R}^D$ alongside its self-reported objective scalar $y_{\text{raw}} \in \mathbb{R}$ \cite{LLaMEA2024}. The evaluation harness discards $y_{\text{raw}}$ unconditionally \cite{LLaMEA2024}. In stochastic search environments, extreme negative noise perturbations ($z_k \ll 0$) can generate deceptive objective drops; accepting self-reported values would allow unconverged points that benefited from fortunate stochastic draws to establish artificial parent baselines, inducing false elitism and permanently stalling evolutionary progress \cite{Jin2005, Qian2020}.

To compute an uncorrupted selection signal and enforce strict anti-hallucination guarantees within the LLaMEA $(1+1)$ evolutionary loop \cite{LLaMEA2024}, the evaluator overrides self-reported outputs by intercepting the candidate coordinate $\mathbf{x}^*$. The harness verifies boundary compliance ($\mathbf{x}^* \in [\mathbf{lb}, \mathbf{ub}]^D$) and numerical finiteness ($\texttt{NaN}$, $\texttt{Inf}$ checks) before evaluating $\mathbf{x}^*$ directly on the clean objective oracle \cite{LLaMEA2024}:
\begin{equation}\label{eq:clean_oracle_query}
    y_{\text{clean}} = f_{\text{clean}}(\mathbf{x}^*)
\end{equation}
The underlying distance to the known analytical minimum is quantified via the absolute spatial optimality gap:
\begin{equation}\label{eq:clean_spatial_gap}
    \Delta y = |y_{\text{clean}} - f^*|
\end{equation}
While standard foundational LLaMEA aggregates the Area Over the Convergence Curve (AOCC) across deterministic multi-function suites \cite{LLaMEA2024}, our single-problem stochastic discovery engine scores individual candidate algorithms via the negated optimality gap:
\begin{equation}\label{eq:fitness_assignment}
    \mathcal{F} = -\Delta y = -|y_{\text{clean}} - f^*|
\end{equation}
Because the $(1+1)$ selection rule in LLaMEA maximizes fitness ($\mathcal{A}_{\text{parent}}^{(g+1)} \gets \mathcal{A}_{\text{child}}^{(g)} \iff \mathcal{F}(\mathcal{A}_{\text{child}}) \ge \mathcal{F}(\mathcal{A}_{\text{parent}})$), driving $\mathcal{F} \to 0$ directly minimizes the true distance to the global minimizer. Evaluating candidate solutions through the clean oracle while restricting internal search logic strictly to corrupted feedback $f_{\text{noisy}}(x_k)$ decouples genuine spatial optimization from transient noise spikes, eliminating false elitism at the meta-selection level \cite{Jin2005, Qian2020, LLaMEA2024}.

Beyond passive exception handling, the evaluation harness incorporates an active evolutionary stagnation monitor to prevent the $(1+1)$ meta-search from stalling on unviable algorithmic trajectories \cite{LLaMEA2024}. Because single-parent evolution strategies lack demographic population diversity, the generative model can occasionally become trapped in repetitive, localized failure loops—iteratively generating minor syntactical mutations of an incumbent architecture that repeatedly crash or fail to achieve measurable performance gains.

To supervise and steer the evolutionary trajectory, the evaluator maintains an internal consecutive failure counter, denoted as $C_{\text{failures}}$. The state of $C_{\text{failures}}$ updates dynamically across generational transitions:
\begin{itemize}
    \item \textbf{Valid Execution and Counter Reset:} When an offspring executes successfully within domain and budget constraints, the evaluator computes its clean oracle fitness and resets the tracker ($C_{\text{failures}} \gets 0$).
    \item \textbf{Failure Interception and Counter Increment:} When a candidate script fails static AST compilation, triggers an unhandled runtime exception, or exceeds execution deadlines, the sandbox assigns a tiered failure penalty (as detailed in Section~\ref{sec:method_sandbox_defenses}) and increments the tracker ($C_{\text{failures}} \gets C_{\text{failures}} + 1$).
\end{itemize}

When the monitor detects three consecutive non-improving or crashing generations ($C_{\text{failures}} \ge 3$), it classifies the evolutionary search as stagnated and dynamically injects a structural $[\textsc{Meta-Feedback}]$ directive into the feedback buffer $\mathcal{T}_{\text{feedback}}$ \cite{LLaMEA2024}:
\begin{quote}
    \footnotesize\ttfamily
    $[\textsc{Meta-Feedback}]$: The last 3 generations failed due to repeated execution errors or lack of progress. Abandon the current step-adaptation logic. Pivot immediately to a robust population-based heuristic: implement a vectorized Particle Swarm Optimization (PSO) or a covariance-matrix inspired Gaussian mutation strategy with explicit boundary clamping and numerical stability guards ($\epsilon = 10^{-8}$) \cite{Kennedy1995, Hansen2001}.
\end{quote}
This intervention forces an exploratory paradigm shift within the prompt context, instructing the foundation model to abandon failing algorithmic primitives and pivot toward established continuous metaheuristic archetypes \cite{Kennedy1995, Hansen2001, LLaMEA2024}.

Finally, all evaluated candidate routines are committed to persistent dual-layer storage alongside complete operational telemetry \cite{LLaMEA2024}. Executable Python source code is preserved within the content-addressed source registry, while uncorrupted error gaps, wall-clock execution durations, exception tracebacks, and stagnation intervention flags are appended to the relational database \cite{LLaMEA2024}. Preserving these complete generational artifacts enables downstream AST morphological audits, post-hoc benchmarking gauntlets, and non-parametric statistical hypothesis testing without requiring repeated execution of the generative synthesis loop \cite{LLaMEA2024, deNobel2024}.

\section{Execution Engine}\label{sec:execution_engine}

Autonomous algorithm generation runs unverified Python code dynamically at each generation, risking CPU deadlocks, memory leaks, and unintended host operating system calls \cite{LLaMEA2024}. The compilation engine mitigates these failure modes through Abstract Syntax Tree (AST) validation, detached namespace isolation, and strict wall-clock time bounding \cite{LLaMEA2024}.

\textbf{Structural Compilation and AST Security Sanitization.}
The compiler takes the candidate code string, target dimension $D$, and execution settings \cite{LLaMEA2024}. Before compilation, the raw string passes through an AST node visitor \cite{LLaMEA2024}:
\begin{itemize}
    \item \textbf{AST Parsing and Block Verification:} The parser walks the AST hierarchy, rejecting empty method bodies, malformed indentation blocks, or missing \texttt{pass} statements prior to byte compilation \cite{LLaMEA2024}.
    \item \textbf{Scientific Library Whitelisting and Solver Restrictions:} Standard numerical modules (\texttt{numpy}, \texttt{math}, \texttt{random}) are permitted \cite{LLaMEA2024}. Black-box optimization solvers---specifically subpackages within \texttt{scipy.optimize}---are explicitly blocked to force the model to synthesize custom search logic.
    \item \textbf{System Calls and Dynamic Primitives:} Operating system modules (\texttt{os}, \texttt{sys}, \texttt{subprocess}, \texttt{shutil}, \texttt{socket}, \texttt{importlib}) and dynamic evaluation primitives (\texttt{eval}, \texttt{exec}, \texttt{open}, \texttt{compile}, \texttt{\_\_import\_\_}) cause immediate AST rejection \cite{LLaMEA2024}.
    \item \textbf{Isolated Namespace Execution:} Code passing security validation compiles into an isolated dictionary namespace, preventing variables from leaking into the host runtime environment \cite{LLaMEA2024}.
\end{itemize}

\textbf{Protected Sandboxed Execution and Timeout Interception.}
Generated heuristics occasionally enter infinite loops, encounter singular covariance updates, or trigger recursive step expansions \cite{LLaMEA2024}. Each candidate runs in a detached worker process governed by an enforced 30.0-second limit ($T_{\text{max}} = 30.0\,\text{s}$) \cite{LLaMEA2024}. When runtime exceeds $T_{\text{max}}$, the harness intercepts the stall, terminates the worker via process signals, and logs an \texttt{AlgorithmTimeoutException} \cite{LLaMEA2024}. Floating-point warnings (underflows, invalid square roots, zero divisions) are caught via runtime hooks, logging numerical anomalies while preventing console pollution \cite{LLaMEA2024}.

\textbf{Output Unpacking, Boundary Normalization, and Budget Overrun Verification.}
When execution finishes within the wall-clock threshold, the harness verifies the returned data structure:
\begin{enumerate}
    \item \textbf{Result Unpacking and Array Casting:} The runner extracts spatial vector $\mathbf{x}^*$ and scalar $y_{\text{raw}}$ \cite{LLaMEA2024}. If the script returns scalar values or irregular nested structures, $\mathbf{x}^*$ is cast to a continuous 1D NumPy array ($\mathbf{x}^* \in \mathbb{R}^D$) \cite{LLaMEA2024}.
    \item \textbf{Domain Bounds and Numerical Finiteness:} The coordinate vector is checked for spatial validity \cite{LLaMEA2024}. The return is marked invalid if $\mathbf{x}^* \notin [\mathbf{lb}, \mathbf{ub}]^D$ or if numerical overflow produces non-finite values ($\texttt{NaN}$, $\texttt{Inf}$) \cite{LLaMEA2024}.
    \item \textbf{Budget Overrun Bounds:} An internal counter tracks function calls $k$. To prevent heuristics from exceeding their allocated budget, the engine asserts:
    \begin{equation}\label{eq:budget_overrun_check}
        k \le \lambda_{\text{tol}} \cdot B_{\text{synth}}
    \end{equation}
    where $\lambda_{\text{tol}} = 1.10$ defines a 10\% tolerance margin over budget $B_{\text{synth}} = 1{,}000$. Candidates exceeding this bound are disqualified to maintain parity across evaluations \cite{LLaMEA2024}.
\end{enumerate}

\textbf{Tiered Diagnostic Scoring and Traceback Propagation.}
Candidates failing AST checks, exceeding execution deadlines, or raising unhandled runtime errors receive tiered penalty scores \cite{LLaMEA2024}:
\begin{equation}\label{eq:failure_penalties}
\mathcal{F}_{\text{failure}} =
\begin{cases}
-5.0 \times 10^8, & \text{if Execution Timeout } (t_{\text{wall}} > T_{\text{max}} = 30.0\,\text{s}) \\
-7.0 \times 10^8, & \text{if Runtime Numerical or Dimensional Exception} \\
-1.0 \times 10^9, & \text{if AST Validation, Prohibited Library Import, or Syntax Failure}
\end{cases}
\end{equation}
This tiered assignment maintains clear selection pressure across generations \cite{LLaMEA2024}. Valid but slow routines outrank crashing code, which in turn outranks unparseable syntax \cite{LLaMEA2024}.

For runtime exceptions, the parser extracts the failure line and exception message (e.g., \texttt{LinAlgError: Matrix is singular at line 48}) \cite{LLaMEA2024}. This diagnostic trace is appended to buffer $\mathcal{T}_{\text{feedback}}$, enabling closed-loop semantic self-debugging in subsequent generations \cite{Chen2023, LLaMEA2024}.

\section{Evolutionary Code Discovery and Stochastic Selection}\label{sec:method_llamea}

The meta-optimization search over program space adapts the Large Language Model Evolutionary Algorithm (LLaMEA) paradigm \cite{LLaMEA2024}, employing the generative model as a semantic variation operator. In contrast to classical numeric perturbation operators, the language model refactors continuous heuristic logic, modifies internal state representations, and adjusts search dynamics based on reflective execution feedback \cite{Romera2023, ReflectiveSurvey2025}.

\subsection{The Operational $(1+1)$ Evolutionary Loop}
To prevent token-context saturation and avoid the prohibitive computational latency of evaluating large code populations $(\mu, \lambda)$ \cite{Lange2024}, the synthesis engine executes a single-offspring $(1+1)$ Evolution Strategy across $G = 10$ generations \cite{LLaMEA2024}. 

In each generation $g \in \{1 \dots G\}$, the generative model synthesizes a single offspring algorithm $\mathcal{A}_{\text{child}}$ derived from incumbent parent $\mathcal{A}_{\text{parent}}$ conditioned on a structured prompt context $\mathcal{C}_g$:
\begin{equation}\label{eq:context_assembly}
    \mathcal{C}_g = \left\{ \mathcal{P}_{\text{system}}, \mathcal{H}_{1 \dots g-1}, \mathcal{T}_{\text{feedback}}, \mathcal{I}_{\text{directive}} \right\}
\end{equation}
The prompt context integrates four informational streams:
\begin{enumerate}
    \item \textbf{System Specification ($\mathcal{P}_{\text{system}}$):} Enforces the black-box interface contract (Equation~\ref{eq:candidate_interface_call}), setting dimensional boundaries ($[-5.0, 5.0]^D$) and the synthesis evaluation ceiling ($B_{\text{synth}} = 1{,}000$) \cite{Hansen2010, LLaMEA2024}.
    \item \textbf{Historical Archive ($\mathcal{H}_{1 \dots g-1}$):} An indexed registry recording previously generated algorithm identifiers and their uncorrupted error scores, acting as short-term tabu memory to prevent redundant code synthesis \cite{LLaMEA2024}.
    \item \textbf{Incumbent State ($\mathcal{T}_{\text{feedback}}$):} Contains the complete Python source code of active parent $\mathcal{A}_{\text{parent}}$, its uncorrupted oracle error $\Delta y_{\text{clean}}$, and diagnostic traceback frames from prior runtime faults \cite{Chen2023, LLaMEA2024}.
    \item \textbf{Evolutionary Directive ($\mathcal{I}_{\text{directive}}$):} Scaffolding instructions (ablated according to the \textsc{Baseline}, \textsc{Guided}, \textsc{Thinking}, or \textsc{Vectorization} strategy) prompting the model to diagnose failure modes and synthesize algorithmic revisions \cite{LLaMEA2024}.
\end{enumerate}

\subsection{False Elitism and the $K$-Pass Stochastic Resampling Policy}
Under deterministic evaluations ($\sigma = 0.0$), selection follows a standard elitist replacement rule: $\mathcal{A}_{\text{parent}}^{(g+1)} \gets \mathcal{A}_{\text{child}}^{(g)}$ if and only if $\mathcal{F}(\mathcal{A}_{\text{child}}) > \mathcal{F}(\mathcal{A}_{\text{parent}})$ \cite{LLaMEA2024}. However, when optimizing on stochastic landscapes ($\sigma > 0.0$), unmitigated greedy selection is vulnerable to false elitism \cite{Jin2005, Qian2020}. 

If an inferior child heuristic evaluates coordinates that receive an extreme negative perturbation ($z_k \ll 0$), it yields an artificially superior fitness score \cite{Jin2005}. Under standard elitism, this over-evaluated child replaces the parent and creates an unachievable fitness ceiling \cite{Qian2020}. Subsequent offspring with genuinely superior search mechanisms are consistently rejected because realistic evaluation passes cannot match the outlier score of the parent, causing premature evolutionary stagnation \cite{Jin2005, Qian2020}.

To resolve this vulnerability, the synthesis loop implements a **Stochastic Parent Resampling Policy** \cite{Jin2005, Qian2020}. At the conclusion of generation $g$, incumbent parent $\mathcal{A}_{\text{parent}}$ is re-evaluated across $K = 3$ independent stochastic passes using fresh random seeds \cite{Jin2005}. The parent selection threshold is updated to its empirical sample mean:
\begin{equation}\label{eq:parent_resampling}
    \bar{\mathcal{F}}_{\text{parent}} = \frac{1}{K} \sum_{k=1}^{K} \mathcal{F}^{(k)}\left(\mathcal{A}_{\text{parent}}\right)
\end{equation}
where $\mathcal{F}^{(k)}(\mathcal{A}_{\text{parent}})$ represents the scalar fitness computed via Equation~\ref{eq:fitness_assignment} on stochastic evaluation pass $k$. Averaging over $K=3$ independent passes causes transient noise spikes to decay, ensuring that selection pressure favors heuristics with structural variance tolerance over temporary stochastic anomalies \cite{Arnold2003, Jin2005}.

\section{Prompt Scaffolding Archetypes}\label{sec:method_prompts}

In Large Language Model Evolutionary Algorithms, prompt scaffolding defines the primary semantic interface governing how the foundation model explores algorithmic space \cite{LLaMEA2024}. To isolate how cognitive constraints, explicit domain knowledge, and structural code formatting influence the synthesis of continuous black-box optimizers, the framework establishes four distinct prompt scaffolding archetypes serving as independent experimental treatments (summarized in Table~\ref{tab:prompt_scaffoldings}).

\begin{table}[htbp]
\centering
\small

\toprule
\textbf{Archetype} & \textbf{Core Scaffolding Mechanism} & \textbf{Injected Inductive Bias \& Template Elements} \\
\midrule
\textsc{Baseline} & Minimalist Experimental Control & Invariant black-box interface contract ($D$, $[-5.0, 5.0]^D$, budget $B_{\text{synth}}$); zero topological hints or noise notifications. \\
\addlinespace
\textsc{Guided} & Domain-Specific Expert Priors & Regime-aware code recipes: DE mutation templates and covariance updates under clean regimes; budgeted $k$-sample re-evaluation ($\le 20\%$ budget) under noise. \\
\addlinespace
\textsc{Thinking} & Socratic Chain-of-Thought (CoT) & Mandatory pre-code deliberation analyzing exploration-exploitation schedules, step-size decay, and robust statistical estimators (mean vs. median). \\
\addlinespace

\bottomrule
\end{tabularx}

\begin{enumerate}
    \item \textbf{\textsc{Baseline} (\texttt{baseline.j2}):} Operates as the unconstrained experimental control. The prompt supplies strictly the software interface signature, problem dimensionality $D$, spatial domain bounds ($[-5.0, 5.0]^D$), and evaluation budget $B_{\text{synth}} = 1{,}000$. It contains no domain-specific guidance regarding landscape conditioning, multimodality, or evaluation noise. This configuration isolates the LLM's raw internal prior to discover continuous optimization heuristics driven purely by evolutionary selection pressure.
    
    \item \textbf{\textsc{Guided} (\texttt{guided.j2}):} Injects explicit, domain-expert mathematical priors tailored to the evaluation regime. On deterministic surfaces, the template recommends foundational metaheuristics—including Differential Evolution mutation mechanisms ($\mathbf{v}_i = \mathbf{x}_{r_1} + F \cdot (\mathbf{x}_{r_2} - \mathbf{x}_{r_3})$) and covariance matrix adaptation principles. On stochastic surfaces, it explicitly warns of heteroscedastic noise and suggests implementing an internal re-evaluation helper ($\texttt{\_robust\_eval}$) with a $k$-sample mean estimator constrained to consume $\le 20\%$ of the total evaluation budget. This archetype measures the maximum generative ceiling when the model functions as a co-pilot initialized with expert human priors.
    
    \item \textbf{\textsc{Thinking} (\texttt{thinking.j2}):} Enforces structured Socratic Chain-of-Thought deliberation prior to source code emission. Before outputting Python blocks, the model must populate a mandatory Markdown analysis section addressing key conceptual questions: (i) diagnosing previous iteration bottlenecks, (ii) balancing exploration against exploitation through adaptive step-size decay, and (iii) identifying which statistical metric (mean vs. median) provides reliable candidate ranking without exhausting the evaluation budget. This tests whether latent cognitive planning improves algorithmic correctness over immediate code synthesis.
    
    \item \textbf{\textsc{Vectorization} (\texttt{vectorization.j2}):} Imposes an architectural array-oriented programming constraint. The template mandates representing candidate populations as 2D NumPy arrays of shape $(N, D)$ and prohibits slow scalar Python iteration loops across population members. Mutation, recombination, and boundary clipping must be executed via vectorized array slicing and matrix broadcasting. This configuration evaluates whether enforcing computational execution efficiency assists or constrains the mathematical creativity of the synthesized heuristics.
\end{enumerate}

\section{Experimental Gauntlet}\label{sec:method_gauntlet}

The experimental protocol divides into two phases: prompt ablation and comparative baseline validation.

\textbf{Phase 1: Intra-Framework Prompt Ablation.}
Phase 1 tests the four prompt configurations (BASELINE, THINKING, VECTORIZATION, GUIDED) across five BBOB objective functions spanning distinct topological properties:
\begin{itemize}
\item \textbf{$f_1$ (Sphere):} Unimodal separable surface for measuring convergence rate and gradient alignment.
\item \textbf{$f_8$ (Rosenbrock):} Non-separable surface with a curved parabolic valley, testing search through low-to-moderate conditioning.
\item \textbf{$f_{10}$ (Ellipsoidal):} Ill-conditioned unimodal surface with an extreme condition number ($10^6$), assessing anisotropic coordinate scaling.
\item \textbf{$f_{15}$ (Rastrigin):} Multimodal surface with a sinusoidal grid overlaying a global quadratic basin, testing local optima escape.
\item \textbf{$f_{21}$ (Gallagher 101 Peaks):} Asymmetric multimodal surface containing 101 randomly distributed Gaussian peaks, evaluating basin hopping without global gradient structure.
\end{itemize}
Runs execute under heteroscedastic noise regimes ($\text{CV} \in \{0.05, 0.10\}$) in dimension $D = 5$ to produce candidate optimizers for downstream testing.

\textbf{Phase 2: Comparative Benchmarking and Dimensional Transfer.}
Phase 2 benchmarks the top-performing synthesized algorithms against three established numerical optimizers: Covariance Matrix Adaptation Evolution Strategy (CMA-ES) \cite{Hansen2001}, Differential Evolution (DE) \cite{Storn1997}, and Particle Swarm Optimization (PSO) \cite{Kennedy1995}.

The post-hoc benchmark evaluates two settings:
\begin{enumerate}
\item \textbf{Deterministic Baseline Validation ($\text{CV} = 0.0$):} Checks whether heuristics evolved under noise maintain convergence rates on clean objective landscapes.
\item \textbf{Stochastic Robustness Validation ($\text{CV} > 0.0$):} Measures the performance degradation of standard baseline optimizers against synthesized heuristics as noise variance increases.
\end{enumerate}
To test structural generalizability, algorithms evolved in dimension $D = 5$ are evaluated directly on higher dimensions ($D \in \{10, 20\}$) without code modifications or parameter retraining.

\section{Evaluation Metrics}\label{sec:method_stats}

Benchmarking runs across $N_{\text{trials}} = 30$ independent random seeds for each problem instance, noise level, and search dimension. Performance is assessed using anytime convergence curves, Empirical Cumulative Distribution Functions (ECDFs), and non-parametric hypothesis testing.

\textbf{Anytime Convergence Trajectory Analysis.}
Optimization dynamics are logged by tracking the uncorrupted optimality gap at each evaluation step $k \in \{1 \dots B\}$:
\begin{equation}\label{eq:clean_delta_step}
\Delta f(x_k) = \left| f_{\text{clean}}(x_k) - f(x^*) \right|
\end{equation}
The anytime performance metric records the best uncorrupted error found up to step $k$:
\begin{equation}\label{eq:best_so_far_trajectory_eval}
\Delta f_{\text{best}}(k) = \min_{j \in \{1 \dots k\}} \left| f_{\text{clean}}(x_j) - f(x^*) \right|
\end{equation}
Across $N_{\text{trials}} = 30$ runs, performance is plotted as geometric mean trajectories with shaded standard error bands on logarithmic axes:
\begin{itemize}
\item \textbf{Horizontal Axis ($k$):} Total function evaluations on a logarithmic scale from $1$ to $10^5$.
\item \textbf{Vertical Axis ($\Delta f_{\text{best}}(k)$):} Uncorrupted optimality gap plotted across eight orders of magnitude from $10^2$ down to $10^{-8}$.
\item \textbf{Stagnation Tracking:} Horizontal plateauing marks the budget threshold where heuristics encounter premature convergence or variance collapse.
\end{itemize}

\textbf{Empirical Cumulative Distribution Functions (ECDFs).}
To aggregate performance across different problem topographies without scale distortion, empirical cumulative distribution functions (ECDFs) are constructed over a range of target precision thresholds \cite{Hansen2021COCO}.

Let $\Theta$ define $M = 51$ logarithmically spaced precision thresholds spanning eight orders of magnitude:
\begin{equation}\label{eq:target_precision_spectrum}
\Theta = \left\{ 10^{\theta} \mid \theta \in [-8.0, 2.0], \, \Delta \theta = 0.2 \right\}
\end{equation}
For $N_{\text{trials}} = 30$ runs across problem instances $I$, the empirical attainment function at threshold $\tau \in \Theta$ and budget step $k$ is given by:
\begin{equation}\label{eq:ecdf_formula}
F(k, \tau) = \frac{1}{|I| \cdot N_{\text{trials}}} \sum_{i \in I} \sum_{r=1}^{N_{\text{trials}}} \mathbb{I}\left[ \Delta f_{\text{best}}^{(i, r)}(k) \le \tau \right]
\end{equation}
where $\mathbb{I}[\cdot]$ is the indicator function:
\begin{equation}\label{eq:indicator_function}
\mathbb{I}\left[ \Delta f_{\text{best}}^{(i, r)}(k) \le \tau \right] =
\begin{cases}
1, & \text{if } \Delta f_{\text{best}}^{(i, r)}(k) \le \tau \\
0, & \text{if } \Delta f_{\text{best}}^{(i, r)}(k) > \tau
\end{cases}
\end{equation}
The Area Under the ECDF Curve ($\text{AUC-ECDF}$) integrates empirical attainment across logarithmic evaluation budgets:
\begin{equation}\label{eq:auc_ecdf}
\text{AUC-ECDF} = \frac{1}{|\Theta| \log_{10}(B)} \int_{1}^{B} \sum_{\tau \in \Theta} F(k, \tau) \, d(\log_{10} k)
\end{equation}
Higher $\text{AUC-ECDF}$ values denote faster convergence and higher solution rates across precision targets.
