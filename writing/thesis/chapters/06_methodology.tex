\chapter{Methodology}\label{chap:methodology}

This chapter details the architectural design, software orchestration, and mathematical formulation of the non-deterministic automated algorithm design pipeline implemented in this thesis. To isolate the adaptive mechanics of Large Language Model code discovery under fitness uncertainty, our framework tightly couples generative foundation models with a controlled, noise-injected execution sandbox. The pipeline operates as a closed-loop evolutionary system designed to transition Python source-code structures from deterministic assumptions to noise-resilient operational behaviors. The following sections delineate our environmental wrapper implementation, the closed-loop evolutionary orchestration strategy, the structural code sanitization and tracking layers, and the statistical evaluation metrics designed to measure cross-environment generalizability.

%-------------------------------------------------------------------------------
\section{The Stochastic Sandbox and Optimality-Gap Heteroscedastic Noise}\label{sec:method_sandbox}

To systematically evaluate whether Large Language Models can design optimization heuristics capable of surviving real-world sensory uncertainty, candidate code must be subjected to controlled, non-deterministic operational conditions \cite{Jin2005}. This research utilizes the continuous Black-Box Optimization Benchmark (BBOB) suite as its foundational testbed \cite{Hansen2010}. However, because standard benchmark instances are strictly deterministic, evaluating noise resilience required formulating an environmental noise injection wrapper over objective evaluations.

In continuous stochastic optimization literature, sensory uncertainty is predominantly simulated using either static additive white Gaussian noise \cite{Jin2005},
\begin{equation}\label{eq:static_noise_lit}
    f_{\text{noisy}}(x) = f_{\text{clean}}(x) + \mathcal{N}(0, \sigma^2)
\end{equation}
or naive point-wise multiplicative noise \cite{Jin2005},
\begin{equation}\label{eq:naive_multiplicative_lit}
    f_{\text{noisy}}(x) = f_{\text{clean}}(x) \cdot \left(1 + \mathcal{N}(0, \text{CV}^2)\right)
\end{equation}
where $x \in \mathbb{R}^D$ denotes a $D$-dimensional coordinate vector in the search space, $f_{\text{clean}}(x) \in \mathbb{R}$ represents the true deterministic objective evaluation, $\sigma^2 \in \mathbb{R}^+$ is a fixed scalar variance, $\text{CV} \in \mathbb{R}^+$ is the dimensionless Coefficient of Variation ($\text{CV} = \sigma / \mu$), and $f_{\text{noisy}}(x) \in \mathbb{R}$ is the corrupted observation returned to the search heuristic.

When applied across a heterogeneous suite of continuous functions, both standard models exhibit fundamental theoretical breakdowns \cite{Hansen2010}. Static unscaled noise (Equation~\ref{eq:static_noise_lit}) applies a fixed variance $\sigma^2$ regardless of objective magnitude. On flat landscapes where objective values near the optimum approach $10^{-5}$, static noise creates an overwhelmingly low Signal-to-Noise Ratio (SNR), swamping the true gradient signal. Conversely, on steep landscapes where objective values scale to $10^6$, an additive noise magnitude represents a negligible fraction of the objective range, allowing algorithms to exploit clean gradients without acquiring genuine noise tolerance \cite{Hansen2010}.

On the other hand, naive multiplicative noise (Equation~\ref{eq:naive_multiplicative_lit}) treats noise as proportional to the \textit{coordinate system artifact} of the function—the raw value $f_{\text{clean}}(x)$. Because $f_{\text{clean}}(x)$ includes the arbitrary constant shift of the global optimum $f(x^*)$, it contains no genuine information regarding spatial distance to the minimum. If a landscape is redefined as $g(x) = f(x) + 10,000$, naive multiplicative noise explodes by orders of magnitude with no scientific justification, obliterating the underlying basin topology.

To explicitly demonstrate this structural collapse, consider BBOB Function $f_{21}$ (Gallagher's Gaussian 101 Peaks). The true optimum is shifted to $f(x^*) \approx 40.78$, and the function's dynamic range spans roughly $50$ units (from $40$ to $90$). Under naive multiplicative noise with a coefficient of $\text{CV} = 0.05$, a candidate evaluation sitting deep within the global optimum basin at $f_{\text{clean}}(x) = 41.0$ receives a standard deviation of:
\begin{equation}\label{eq:f21_naive_std}
    \sigma = 0.05 \cdot 41.0 = 2.05
\end{equation}
A perturbation of $\pm 2.05$ represents $4\%$ of the entire dynamic range of the function. For a highly multimodal landscape where height differences between local Gaussian peaks are often just $2$ to $5$ units, this noise level completely obliterates the basin topology. If an LLM-generated algorithm evaluates two candidate solutions, $x_a$ ($f = 41.5$) and $x_b$ ($f = 42.0$), the naive formula generates extreme overlapping distributions: $f_{\text{noisy}}(x_a) \sim \mathcal{N}(41.5, 2.075^2)$ and $f_{\text{noisy}}(x_b) \sim \mathcal{N}(42.0, 2.1^2)$. The noise frequently inverts the objective ranking, providing the search heuristic with zero useful gradient signal.

Furthermore, while standard point-wise proportional noise maintains constant SNR across macro-scales, pure multiplicative noise introduces a zero-noise sanctuary near convergence. As candidate search trajectories approach $f(x^*) = 0$, local noise variance mathematically vanishes:
\begin{equation}\label{eq:vanishing_variance}
    \lim_{f(x) \to f(x^*)} \operatorname{Var}\left(f_{\text{noisy}}(x)\right) = 0
\end{equation}
where $\operatorname{Var}(\cdot)$ denotes the mathematical variance operator. This vanishing variance allows optimizers to exploit uncorrupted signals precisely at the point of convergence, defeating the purpose of a stochastic benchmark.

To resolve these limitations, this thesis formulates the \textbf{Optimality-Gap Heteroscedastic Noise Model with a Non-Zero Baseline Noise Floor}. We propose replacing raw-value multiplicative noise with a gap-anchored formulation. For any evaluation coordinate $x_k \in \mathbb{R}^D$ generated at step $k$, the point-wise standard deviation $\sigma_{\text{dynamic}}(x_k)$ scales strictly with absolute objective elevation relative to the known global minimum $f(x^*)$, while enforcing a positive noise floor $\sigma_{\text{floor}} > 0$:
\begin{equation}\label{eq:proportional_dynamic_std}
    \sigma_{\text{dynamic}}(x_k) = \text{CV} \cdot \left| f_{\text{clean}}(x_k) - f(x^*) \right| + \sigma_{\text{floor}}
\end{equation}
where $\text{CV} \ge 0$ parameterizes the relative noise intensity, $\left| f_{\text{clean}}(x_k) - f(x^*) \right|$ represents the true objective distance to the global optimum, and $\sigma_{\text{floor}} = 10^{-8}$ prevents Equation~\ref{eq:vanishing_variance} from establishing an artificial zero-noise sanctuary.

Because the BBOB suite is a controlled benchmarking testbed, $f(x^*)$ is known \textit{a priori} to the evaluation sandbox (acting as an omniscient wrapper) but remains strictly hidden from the candidate algorithm. The corrupted evaluation observation returned to the candidate search logic at step $k$ is formulated as:
\begin{equation}\label{eq:proportional_gaussian_noise}
    f_{\text{noisy}}(x_k) = f_{\text{clean}}(x_k) + z_k, \quad z_k \sim \mathcal{N}\left(0, \sigma_{\text{dynamic}}^2(x_k)\right)
\end{equation}
where $z_k \in \mathbb{R}$ is a zero-mean Gaussian random perturbation variable sampled independently at evaluation step $k$.

The continuous probability density function $p(z_k)$ governing the additive perturbation $z_k$ at evaluation step $k$ is formally expressed as:
\begin{equation}\label{eq:gaussian_pdf_dynamic}
    p(z_k) = \frac{1}{\sqrt{2\pi \sigma_{\text{dynamic}}^2(x_k)}} \exp\left( -\frac{z_k^2}{2\sigma_{\text{dynamic}}^2(x_k)} \right)
\end{equation}
where $\pi \approx 3.14159$ represents the mathematical constant pi. Because $p(z_k)$ is symmetric around zero ($\mathbb{E}[z_k] = 0$), the noisy objective feedback remains an unbiased estimator of true objective elevation:
\begin{equation}\label{eq:unbiased_expectation}
    \mathbb{E}[f_{\text{noisy}}(x_k)] = f_{\text{clean}}(x_k)
\end{equation}

Anchoring the variance dynamically to the optimality gap via Equation~\ref{eq:proportional_dynamic_std} establishes three mathematically vital properties for Automated Algorithm Design:
\begin{enumerate}
    \item \textbf{Oracle Preservation:} As search trajectories approach the global minimum ($f_{\text{clean}}(x) \to f(x^*)$), the variance smoothly transitions to $\sigma_{\text{floor}} = 10^{-8}$. The true optimum remains uniquely identifiable and statistically distinguishable at all noise levels, ensuring optimizers that successfully converge are rewarded with quiet, accurate readings.
    \item \textbf{Scale-Invariance:} The Signal-to-Noise Ratio (SNR) at any point is bounded by $1/\text{CV}$ regardless of whether the problem is $f_8$ (with a dynamic range of $\sim 10^3$) or $f_{21}$ (with a dynamic range of $\sim 50$). This standardizes environmental pressure across all benchmark topological classes without requiring per-function calibration.
    \item \textbf{Structured Difficulty:} Exploration regions far from the optimum carry high uncertainty, while exploitation regions near the optimum carry low uncertainty. This reflects highly realistic physical noise models where measurement error scales with a system's deviation from equilibrium.
\end{enumerate}

Re-evaluating the $f_{21}$ (Gallagher 101) case study under this gap-anchored model ($\text{CV} = 0.05$), the two points $x_a$ ($f = 41.5$) and $x_b$ ($f = 42.0$) yield vastly superior signal integrity:
\begin{equation}\label{eq:f21_gap_std_a}
    \sigma_{\text{dynamic}}(x_a) = 0.05 \cdot |41.5 - 40.78| + 10^{-8} \approx 0.036
\end{equation}
\begin{equation}\label{eq:f21_gap_std_b}
    \sigma_{\text{dynamic}}(x_b) = 0.05 \cdot |42.0 - 40.78| + 10^{-8} \approx 0.061
\end{equation}
The resulting distributions, $f_{\text{noisy}}(x_a) \sim \mathcal{N}(41.5, 0.036^2)$ and $f_{\text{noisy}}(x_b) \sim \mathcal{N}(42.0, 0.061^2)$, strictly preserve the algorithmic ranking. The basin topology remains intact, allowing intelligently designed heuristics to filter uncertainty and navigate toward convergence.

To explicitly demonstrate the physical mechanics across contrasting topological classes, consider BBOB Function $f_8$ (Rosenbrock). In the official benchmark taxonomy \cite{Hansen2010}, instance transformations apply spatial translations $x^* \in \mathbb{R}^D$ and orthonormal rotation matrices $R \in \mathbb{R}^{D \times D}$ to prevent algorithm over-specialization to coordinate axes. The mathematical formulation of $f_8$ is defined by:
\begin{equation}\label{eq:bbob_f8_formula}
    f_8(x) = \sum_{i=1}^{D-1} \left[ 100 \cdot \left( y_{i+1} - y_i^2 \right)^2 + (1 - y_i)^2 \right] + f_{\text{opt}}
\end{equation}
where $y \in \mathbb{R}^D$ represents the transformed spatial coordinate vector calculated via $y = \max\left(1, \frac{\sqrt{D}}{8}\right) R (x - x^*) + \mathbf{1}$, $\mathbf{1} \in \mathbb{R}^D$ is a vector of ones, and $f_{\text{opt}} \in \mathbb{R}$ represents the shifted global minimum value.

As visualized in Figure~\ref{fig:f8_3d_landscape}, the quadratic term $100 \cdot (y_{i+1} - y_i^2)^2$ constructs a steep parabolic valley curving across the search domain, driving objective deviations $f_{\text{clean}}(x_k) - f_{\text{opt}}$ to magnitudes on the order of $10^3$ near domain boundaries.

Having established a normalized, structurally sound stochastic environment, it is equally critical to define how algorithmic progress is measured within it. To evaluate true optimization capability without corrupting performance tracking with stochastic variance, the experimental framework separates the feedback signal provided to the candidate algorithm from the benchmark's progress measurement. Exposing candidate algorithms to corrupted observations $f_{\text{noisy}}(x_k)$ is necessary to force the discovery of noise-resilient search logic. However, using noisy values to evaluate spatial progress would distort empirical measurement, as an algorithm could receive an unusually favorable negative noise draw ($z_k \ll 0$) that falsely suggests convergence toward $f(x^*)$. To preserve scientific rigor, candidate algorithms rely exclusively on $f_{\text{noisy}}(x_k)$ to guide internal search trajectories and step-size adaptations, while evaluation metrics record the ground-truth distance to the optimum:
\begin{equation}\label{eq:clean_distance_metric}
    \Delta f(x_k) = f_{\text{clean}}(x_k) - f(x^*)
\end{equation}
where $\Delta f(x_k) \in \mathbb{R}^+$ measures the uncorrupted objective distance from coordinate $x_k$ to the global minimum $f(x^*)$. This ensures that reported results reflect actual spatial convergence rather than transient stochastic perturbations. The complete mathematical workflow of this noise injection and progress tracking pipeline is depicted in Figure~\ref{fig:landscape_noise_injection}.

\section{LLM-Driven Evolutionary Code Discovery}\label{sec:method_llamea}

To enable foundation models to autonomously discover optimization heuristics specialized for stochastic environments, this framework adapts the Large Language Model Evolutionary Algorithm (LLaMEA) as its core Automated Algorithm Design engine \cite{LLaMEA2024}. In traditional evolutionary computation, search operators such as crossover and mutation are rigidly defined via pre-coded mathematical routines. Under the Automated Algorithm Design paradigm, the language model itself acts as a highly non-linear, semantic variation operator capable of refactoring entire software architectures, altering search mechanisms, and generating novel algorithmic logic directly from reflective execution feedback.

Rather than synthesizing generic algorithms across pooled benchmark suites, our pipeline executes LLaMEA on each target BBOB objective problem individually. This problem-specific evolutionary setup enables the language model to discover bespoke search logic tailored to the unique geometric and topological properties of a given landscape. The architecture implements a single-offspring $(1+1)$ Evolution Strategy executed directly within the language model's natural language context window. In each generation cycle $g \in \{1 \dots G\}$, where $G = 20$ denotes the maximum evolutionary generation horizon, the language model acts as a code-level mutation operator, generating exactly one candidate child algorithm $\mathcal{A}_{\text{child}}$ derived from the incumbent parent algorithm $\mathcal{A}_{\text{parent}}$. By evaluating a single child per generation, the language model receives an immediate, isolated feedback signal comparing the specific code modifications made in $\mathcal{A}_{\text{child}}$ against the resulting performance differential, enabling precise credit assignment during semantic reflection.

For a targeted continuous objective function $f$, the candidate algorithm $\mathcal{A}$ is allocated a high evaluation budget of $B = 100,000$ function evaluations, executed via the \texttt{IOHexperimenter} platform harness \cite{deNobel2024}. During execution, the candidate algorithm interacts exclusively with noisy observations $f_{\text{noisy}}(x_k)$ to guide its internal search decisions. Simultaneously, the background diagnostic layer tracks the uncorrupted objective distance to the global minimum, $\Delta f(x_k) = f_{\text{clean}}(x_k) - f(x^*)$, across all evaluation steps $k \in \{1 \dots B\}$. The scalar fitness score assigned to algorithm $\mathcal{A}$ on problem $f$ is defined as the logarithmic minimum uncorrupted distance achieved over its trajectory:
\begin{equation}\label{eq:individual_fitness}
    \text{Fitness}(\mathcal{A}) = \log_{10} \left( \min_{k \in \{1 \dots B\}} \Delta f(x_k) \right)
\end{equation}
where $B = 100,000$ represents the budget boundary, $\Delta f(x_k) \in \mathbb{R}^+$ is the true objective distance at evaluation step $k$, and $\text{Fitness}(\mathcal{A}) \in \mathbb{R}$ is the scalar score returned to LLaMEA. Because the task is minimization, lower fitness values indicate superior spatial convergence toward $f(x^*)$.

Under deterministic conditions ($\text{CV} = 0$), evolutionary selection is strictly greedy: $\mathcal{A}_{\text{child}}$ replaces $\mathcal{A}_{\text{parent}}$ if and only if $\text{Fitness}(\mathcal{A}_{\text{child}}) < \text{Fitness}(\mathcal{A}_{\text{parent}})$. However, when operating inside a non-deterministic evaluation sandbox ($\text{CV} > 0$), standard greedy selection is vulnerable to stochastic anomalies. A poorly designed child algorithm may evaluate a sequence of coordinates $x_k$ that happen to receive exceptionally favorable negative noise draws ($z_k \ll 0$), yielding an artificially superior (lower) fitness score. If this over-evaluated child replaces the parent, it becomes an un-killable statistical ghost parent. Subsequent, structurally superior offspring will be repeatedly rejected because they cannot match the ghost parent's mathematically unachievable, noise-inflated baseline.

To eliminate this bottleneck, the evolutionary pipeline enforces a mandatory Stochastic Parent Resampling Policy. At the conclusion of every generation cycle $g$, the incumbent parent algorithm $\mathcal{A}_{\text{parent}}$ is re-evaluated across $K$ independent stochastic passes on problem $f$, dynamically updating its stored baseline fitness to the sample mean score:
\begin{equation}\label{eq:parent_resampling}
    \bar{F}_{\text{parent}} = \frac{1}{K} \sum_{j=1}^{K} \text{Fitness}^{(j)}\left(\mathcal{A}_{\text{parent}}\right)
\end{equation}
where $K = 3$ specifies the number of independent Monte Carlo re-evaluation passes, $\text{Fitness}^{(j)}\left(\mathcal{A}_{\text{parent}}\right) \in \mathbb{R}$ denotes the candidate's aggregate score computed via Equation~\ref{eq:individual_fitness} during the $j$-th pass, and $\bar{F}_{\text{parent}} \in \mathbb{R}$ represents the updated mean fitness threshold assigned to the parent. This Monte Carlo resampling policy ensures that transient noise anomalies decay rapidly, guaranteeing that evolutionary selection pressure favors algorithms possessing genuine structural variance-filtering logic rather than temporary stochastic luck.

During the evolutionary loop, the generated Python source code of $\mathcal{A}_{\text{child}}$ is subjected to strict execution sandboxing. All generated candidate scripts undergo an Abstract Syntax Tree (AST) validation phase prior to execution. This structural validation layer whitelists scientific mathematical libraries such as NumPy and SciPy while outright rejecting unauthorized system modules, thereby preventing arbitrary code execution vulnerabilities. During active evaluation, the sandbox enforces a strict wall-clock execution timeout to safely terminate algorithms that collapse into infinite loops or demonstrate pathologically slow time complexity. If candidate code triggers a fatal runtime exception (e.g., singular matrix inversion, numerical overflow, or bounds violation), the raw Python traceback is intercepted by the sandbox and injected directly into the next generation's prompt context. This operational feedback loop enables the language model to autonomously self-correct its own syntax and logical vulnerabilities across generations.

\section{Experimental Configuration and Foundation Models}\label{sec:method_setup}

To evaluate algorithmic synthesis capabilities across differing levels of model scale and computational reasoning, the evolutionary pipeline is deployed using two distinct foundation models within LLaMEA \cite{LLaMEA2024}. OpenAI's \texttt{gpt-4o} serves as the commercial baseline for state-of-the-art programmatic reasoning and advanced semantic reflection \cite{OpenAI2024}. To evaluate cost-effective, self-hosted algorithm discovery, Meta's open-weights \texttt{Llama-3.1-70B-Instruct} model is hosted locally via vLLM inference endpoints \cite{Llama3}.

Generation parameters are strictly standardized across both foundation models to maintain experimental control. The decoding temperature is fixed at $T = 0.7$, providing an optimal balance between syntactic stability and structural exploration during the code mutation phase. Top-$p$ nucleus sampling is constrained to $0.95$, and the maximum output token limit per generation cycle is capped at $2048$ tokens.

Each LLaMEA discovery run is executed on an individual target BBOB benchmark function instance. Candidate algorithms are evaluated with a function evaluation budget of $B = 100,000$ evaluations per run. The Automated Algorithm Design process iterates for a maximum evolutionary horizon of $G = 20$ generations per problem experiment, providing sufficient mutation depth for the model to refine and stabilize noise-resilient search heuristics.

\section{Cross-Environment Validation Protocols}\label{sec:method_metrics}

To verify whether the autonomously designed heuristics have acquired generalized noise resilience or specialized to specific stochastic conditions, champion algorithms undergo cross-environment validation.

Validation is conducted across representative continuous benchmark functions from the Black-Box Optimization Benchmark suite \cite{Hansen2010}. The experimental protocol benchmarks candidate algorithms across three distinct origin classes:
\begin{enumerate}
    \item \textbf{Clean-Evolved Champions ($\mathcal{A}_{\text{clean}}$):} Algorithms discovered by the language model on problem $f$ when the sandbox is configured with zero environmental noise ($\text{CV} = 0$).
    \item \textbf{Noise-Evolved Champions ($\mathcal{A}_{\text{noisy}}$):} Algorithms discovered by the language model on problem $f$ when the sandbox injects dynamic proportional Gaussian noise ($\text{CV} = 0.1$).
    \item \textbf{Classical Human Baselines ($\mathcal{A}_{\text{baseline}}$):} Standard mathematical implementations of Covariance Matrix Adaptation Evolution Strategy (CMA-ES) \cite{Hansen2001}, Differential Evolution \cite{Storn1997}, and Particle Swarm Optimization \cite{Kennedy1995}.
\end{enumerate}

As detailed in the experimental matrix in Table~\ref{tab:cross_matrix}, these algorithm classes are cross-evaluated in both deterministic ($\text{CV} = 0$) and stochastic ($\text{CV} = 0.1$) testing modes across independent random seed replicates.
